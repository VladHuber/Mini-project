# Mini-project

Учебные задания по Rust — десять независимых крейтов (`task1` … `task10`), каждое задание в своей папке со своим `Cargo.toml`.

Каждая папка — обычный каталог репозитория: можно открыть любой файл прямо на GitHub.

## Требования

- Rust **1.85+** (во всех крейтах `edition = "2024"`)
- Стабильный тулчейн: https://rustup.rs

## Как запускать

Каждое задание — отдельный проект, поэтому команды выполняются из его папки:

```bash
cd task1
cargo run
```

Для заданий с аргументами командной строки:

```bash
cd task7
cargo run -- ERROR app.log
```

## Структура репозитория

```
Mini-project/
├── README.md
├── .gitignore
├── task1/ … task10/
│   ├── Cargo.toml
│   ├── Cargo.lock
│   ├── .gitignore
│   ├── src/
│   │   └── main.rs        (в task10 ещё src/package.rs)
│   ├── assets/            (данные для заданий: log.txt, manager.json, package.json…)
│   └── target/            (сборка, в git не попадает)
└── task6/project/test.rs  (пример кода для анализа)
```

## Данные для запуска

Часть заданий читает файлы из своей папки `assets/`. Те, что содержатся в `.gitignore`, в репозиторий не попали — их нужно подготовить самому:

- **task2** — положите в `task2/assets/` любые файлы (в том числе пару одинаковых), чтобы найти дубликаты.
- **task3** — файл `task3/assets/manager.json` создаётся автоматически при первой команде `add`; при отсутствии файла он считается пустым списком.
- **task4** — путь к обходимому каталогу зашит в коде (`D:/Download` в `task4/src/main.rs`), при необходимости замените на свой.
- **task7** — файл-источник задаётся вторым аргументом и ищется в `assets/` (например, `cargo run -- ERROR app.log`).
- **task9** — ожидает `task9/files/mark.md`.

## Заметки по коду

- Задания писались как учебные: местами есть «зашитые» пути и `unwrap()`, при переносе на другой компьютер их стоит заменить на параметры/корректную обработку ошибок.
- `target/` каждого крейта игнорируется и не коммитится: сборка выполняется локально командой `cargo build` / `cargo run`.
