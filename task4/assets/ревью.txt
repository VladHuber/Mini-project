1. Главная проблема — одинаковые имена файлов

Сейчас ты используешь:

HashMap<String, u64>

Ключ:

file_name

Если есть:

Download/
    image.png
Photos/
    image.png

то второй файл затрёт первый.

Лучше хранить полный путь:

HashMap<PathBuf, u64>

или хотя бы

HashMap<String, u64>

где ключ — это

dir_entry.path().display().to_string()
2. Лишний match

Вот это:

match read_files(...) {
    Ok(files) => files,
    Err(err) => panic!(...)
};

выглядит странно.

Функция возвращает

Result<(), _>

то есть в Ok лежит ().

Проще:

read_files(Path::new("D:/Download"), &mut files)?;

если main тоже возвращает Result.

Я бы вообще сделал:

fn main() -> Result<(), Box<dyn Error>>

Тогда исчезнут почти все panic!.

3. clone()

Здесь:

size_file(val.clone())

val имеет тип:

&u64

Клонировать не нужно.

Можно просто:

size_file(*val)

Это копирование (Copy), а не Clone.

4. Неудачное имя
fn read_files(...)

На самом деле функция не читает файлы.

Она:

обходит директории;
получает метаданные.

Название вроде

collect_files

или

scan_directory

будет понятнее.

5. Магические числа

Сейчас:

1000
1000000
1000000000

Лучше:

const KB: u64 = 1024;
const MB: u64 = KB * 1024;
const GB: u64 = MB * 1024;

Во-первых, это читается лучше. Во-вторых, в большинстве программ используют именно 1024, а не 1000 (если речь о двоичных единицах).

6. return

Например:

if base_size >= 1000 {
    return ...
}

return ...

В Rust обычно пишут без return:

if base_size >= KB {
    format!("{:.2} KB", ...)
} else {
    format!("{:.2} B", ...)
}

Это вопрос стиля, но к нему стоит привыкать.

7. Небольшой стиль

Сейчас:

let entry = entry?;
let dir_entry = entry;

Можно сразу:

let dir_entry = entry?;
